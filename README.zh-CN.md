# Chaos

> 改写历史，或者确保它不被改写。

**状态：** 🚧 设计阶段，尚未开始开发。
为 **Handshake AI Skills Studio 多人游戏挑战赛** 而做（截止日期：2026 年 10 月 30 日）。

## Chaos 是什么？

Chaos 是一款在浏览器里玩的多人角色扮演游戏。每个故事都会把玩家带进一个历史本可以走向另一条路的时刻：一场对话、一个决定、一次改变了一切的偶然。

每位玩家扮演一个角色，拿到只有自己知道的信息和一个**秘密目标（secret objective）**，然后通过几轮对话去影响事件的结局。

**特别之处：** 你用普通的现代语言打字，游戏会把每一句话改写成那个时代的说话方式，比如皇家宫廷、1940 年代的前线、冷战时期的指挥室。你能决定自己*想表达什么*，但没法完全控制它*听起来是什么样子*。

可以和朋友玩，可以和陌生人玩，也可以一个人玩。**所有空着的角色都由 AI 扮演**，真人玩家随时可以接管 AI 的角色。

不需要登录，不需要安装，手机和电脑都能玩。

## 核心设计

| 设计 | 含义 |
|---|---|
| **时代语风（Era Voice）** | 每条消息在别人看到之前，都会先由 LLM 改写成那个时代的说话方式。 |
| **不用等人（Never wait for players）** | 空着的角色由 AI 补上。真人可以中途加入，接管 AI 的角色。 |
| **秘密目标（Secret objectives）** | 每个人都有要隐藏或要达成的事，所以每一句对话都有分量。 |
| **AI 负责演，规则负责判（AI performs, rules decide）** | LLM 负责语风改写、旁白和 AI 角色。结局和胜负由明确的投票和游戏状态决定，**绝不由 LLM 判定**。 |

## 一局游戏怎么玩

1. **选故事**：从大厅选一个故事，或者用房间码 / 邀请链接加入朋友的房间。
2. **领角色**：一张简报卡告诉你：你是谁、正在发生什么、哪些信息只有你知道、你的秘密目标是什么。
3. **按轮对话**：每一轮，每个角色在倒计时结束前说一句话。所有人的话都会被改写成时代语风，并同时揭晓。随后旁白抛出一个新事件，推动剧情。
4. **做出决定**：到了关键决策点，用秘密投票或操作按钮来做选择，而不是靠聊天判断。
5. **结局与揭晓**：游戏状态决定走向哪个结局。旁白讲述结局，所有人的秘密目标被揭晓，显示得分。

目标单局时长：**10–15 分钟**。

### 时代语风示例

| 你输入 | 皇家宫廷 | 1940 年代前线 |
|---|---|---|
| "I'm starving. Is there anything to eat?"（我饿了，有吃的吗？） | *"Pray, my stomach doth wage a most ungracious war — is there naught upon this table to appease it?"* | *"Sarge, rations ran dry two days back. Anything left in that crate?"* |

## 玩家与座位

故事里的每个角色都是一个**座位（seat）**。座位永远处于以下三种状态之一：

| 座位状态 | 什么时候出现 | 其他人看到什么 |
|---|---|---|
| 🤖 **AI** | 还没有真人选这个角色 | 角色名旁边显示 AI 标记 |
| 👤 **真人** | 有玩家加入并选了这个角色 | "🎭 *王后*现在由真人扮演" |
| 🤖⏸ **AI 代打（AI stand-in）** | 真人掉线，或者这一轮超时没发言 | "*王后*暂时由 AI 代打"，真人回来后自动夺回座位 |

**加入和离开的规则**

- **中途加入：** 接管一个 AI 座位。开始之前，先读一段 AI 生成的前情提要（"前情回顾……"）和自己的简报卡。
- **掉线或超时：** 由 AI 代打，游戏不会卡住。
- **最后一轮锁定：** 决定性投票一开始，新来的人只能观战。
- **观战者：** 能看到公开的对话，所有秘密在结局时揭晓。
- **变数角色（Wildcard seat）**（计划中）：故事座位满了以后，如果又来了一个真人，他可以作为隐藏的变数角色加入。这个角色从该故事预先写好的角色池里随机抽取，有自己的秘密目标。其他玩家只会收到提示："这里似乎多了一个人……"

## 大厅

- 大厅展示的是**故事**，不是房间。每张故事卡片有封面图、人数、一句话简介，以及一个 **立即开始** 按钮。
- **自动分配房间：** 优先把玩家放进已经有真人、还有 AI 座位空着的房间；没有的话就新开一间，其他角色由 AI 补上。
- **热门故事自动扩容：** 同一个故事可以同时开好几个房间。
- **私人房间：** 每个房间都有一个 4 位房间码和邀请链接，方便和朋友一起玩。
- 没有真人的房间会**暂停或关闭**，AI 角色绝不会对着空房间自己演。

## 计分（草案，每个故事再细化）

| 行为 | 得分 |
|---|---|
| 完成你的秘密目标 | ✔ |
| 猜中其他玩家的秘密目标 | ✔ |
| 入戏加分（由 AI 评判，权重很小） | ✔ |

入戏加分是唯一由 AI 评判的分数。结局和目标是否完成，由游戏状态和投票决定。

## 设计原则

- **AI 负责演，规则负责判。** 结果可预测、公平，容易 debug，也能防住 prompt injection（提示词注入）。
- **30 秒上手。** 一张简报卡，一个明确目标，每轮只做一件事。
- **一个真人也好玩。** 所有空座位都由 AI 补上。
- **手机优先（Mobile-first）。** 消息简短，每轮提供 2–3 句 AI 建议台词，按钮够大、好点。
- **永不卡住。** 超时机制、AI 代打和失败兜底，保证每个房间都能继续进行。

## 技术架构（计划中）

```
浏览器（手机 / 电脑）
   │  POST /api/action                 加入、发言、投票
   │  GET  /api/state?room=…&seat=…    轮询，按座位返回视图
   ▼
Serverless API
   ├─ 游戏引擎：applyAction(state, action) → newState   （纯函数，结果确定）
   ├─ LLM 调用：时代语风、AI 角色、旁白、前情提要
   └─ 条件写入（版本号检查）
   ▼
状态存储（强一致性）
```

- **服务器是唯一的数据来源（single source of truth）。** 客户端只负责提交操作和显示状态。
- **按座位返回视图。** 隐藏信息（秘密目标、私有线索）在服务器端就过滤掉，而不只是在界面上藏起来。
- **条件写入（Conditional writes）。** 每个房间状态都有版本号，只有版本号没被改过时写入才会成功，以此防止 race condition（竞态条件）。
- **轮询（Polling）。** 按轮进行的玩法能容忍 1–2 秒延迟，所以不需要常驻的 WebSocket 服务器。
- **故事即数据。** 每个故事是一个配置文件，包含角色、简报、秘密目标、决策点、结局和变数角色池。新增故事只需要加一个文件，不用写代码。
- **LLM 的 API key 只存放在服务器端。**

**技术栈（暂定）：** React + Vite + Tailwind · Serverless functions（Vercel）· 状态存储待定（例如 Upstash Redis 或 Supabase）· LLM 提供商待定

## 安全与成本控制

- **限速：** 按玩家、按房间限制频率，并设每日用量上限。
- **没有真人，就没有 AI：** 没有真人玩家的房间会暂停，不会为空房间调用 LLM。
- **内容审核：** 审核玩家输入；用 system prompt 约束所有 AI 输出；对敏感的历史题材谨慎处理。
- **防提示词注入：** 玩家输入的文字只被当作内容处理，结局永远不由 LLM 决定。
- **失败兜底：** 如果 LLM 调用失败或超时，就直接发送原文，保证对话不会卡死。
