Multiplayer historical role-play party game for the Handshake AI Skills Studio Multiplayer Game Challenge.
**Deadline: 2026-10-30 11:59 PM PT.** Feature freeze 10/27, target submission 10/29.

## Where things are

- `README.md` — design doc (source of truth for concept & architecture). `README.zh-CN.md` is a personal translation; do not keep it in sync.
- `docs/spec.md` — game rules & story script (to be written)

## Commands

- `npm install` — install dependencies (Node 24)
- `npm run dev` — frontend + `/api` together at http://localhost:5173 (also reachable from a phone on the same Wi-Fi via the "Network" URL Vite prints)
- `npm run build` — production build into `dist/`
- `npm run format` — format all files with Prettier

`/api/*.js` files export Web-standard handlers (`export function GET(request)` → `Response`). Locally they are served by `dev/vite-api-plugin.js`; on Vercel the same files run as functions — no `vercel dev` or login needed.

## Architecture rules (non-negotiable)

- The server is the single source of truth. Clients only submit actions and render state.
- Hidden information is filtered on the server, in one place (`server/engine/view.js`). Never send a secret to a client and hide it in the UI.
- Seats are authenticated by a random `seatToken`, never by seat name/id alone.
- Every state write is a conditional write on `version`.
- Endings, votes and scores are decided by game rules. The LLM only performs (voice, narration, AI lines).
- LLM prompts never contain another seat's secrets. The narrator never sees any secrets.
- Every LLM call has a timeout and a fallback, so the game never stalls.
- No background timers: rounds advance lazily when a request sees an expired deadline.

## Code conventions

- JavaScript (ES modules), JSDoc for shared data shapes. No TypeScript.
- `api/` holds thin Vercel handlers only; logic lives in `server/` (files in `api/` become functions).
- Game engine is pure functions with tests.
- Stories are data files in `stories/`, not code.
- Only `server/llm/client.js` knows which LLM provider is used.

## Secrets (this repo is PUBLIC)

- API keys live only in `.env` (gitignored). Never commit them, never put them in frontend code.
- `.env.example` lists variable names only, no values.

## Git workflow

- `main` is always playable. Work on branches (`feat/…`, `fix/…`, `chore/…`, `docs/…`) and merge via Pull Request.
- One PR = one thing. Test on the Vercel Preview URL before merging.
- Merge with "Create a merge commit", not squash: Vercel Hobby only deploys commits authored by the project owner (Yuqi).
- Commit after each small working step. Message format: `feat: …`, `fix: …`, `docs: …`, `chore: …`.
- Line endings are enforced by `.gitattributes` (LF).
